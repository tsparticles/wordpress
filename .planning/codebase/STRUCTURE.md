# Codebase Structure

**Analysis Date:** 2026-04-10

## Directory Layout

```text
wordpress/
├── src/                    # Source code for block editor, save/view runtime, and plugin loader catalog
│   ├── plugins/            # tsParticles module catalogs grouped by category
│   │   ├── interactions/   # Interaction plugin sub-catalogs
│   │   └── plugins/        # Plugin sub-catalog helpers (easings, exports, emitter shapes)
│   ├── block.json          # Block metadata, attributes, and script/style entry mapping
│   ├── index.js            # Block registration entry for editor
│   ├── edit.js             # Gutenberg edit UI
│   ├── save.js             # Gutenberg save serialization
│   ├── view.js             # Frontend hydration/runtime entry
│   ├── load.js             # Plugin aggregation and load dispatcher
│   └── utils.js            # Generic plugin descriptor/handler helpers
├── build/                  # Generated assets consumed by WordPress register_block_type
├── assets/                 # Plugin images and WordPress.org media
├── languages/              # Translation template files (.pot)
├── scripts/                # Repository automation scripts
├── .github/workflows/      # CI workflow definitions
├── wordpress-particles.php # PHP plugin bootstrap and WordPress hook registration
├── package.json            # NPM package metadata, scripts, dependencies
└── readme.txt              # WordPress plugin listing metadata and changelog
```

## Directory Purposes

**`src/`:**
- Purpose: Canonical implementation for block behavior and runtime logic.
- Contains: JavaScript modules (`*.js`), Sass styles (`*.scss`), and metadata (`block.json`).
- Key files: `src/index.js`, `src/edit.js`, `src/save.js`, `src/view.js`, `src/load.js`, `src/block.json`.

**`src/plugins/`:**
- Purpose: Maintain tsParticles capability catalogs by concern domain.
- Contains: Category modules (`bundles.js`, `effects.js`, `presets.js`, etc.) and nested sub-catalog builders.
- Key files: `src/plugins/bundles.js`, `src/plugins/interactions/index.js`, `src/plugins/plugins/index.js`, `src/plugins/updaters.js`.

**`build/`:**
- Purpose: WordPress-consumable compiled output generated by `wp-scripts build`.
- Contains: Compiled JS/CSS chunks and asset manifests.
- Key files: `build/view.js`, `build/view.asset.php`, `build/style-index.css`.

**`scripts/`:**
- Purpose: Release/version automation.
- Contains: Node scripts for synchronizing version numbers.
- Key files: `scripts/postversion.js`.

**`languages/`:**
- Purpose: Internationalization artifacts.
- Contains: Translation template files.
- Key files: `languages/tsparticles-block.pot`.

**`assets/`:**
- Purpose: Distribution visuals.
- Contains: Banner, icon, screenshot image files.
- Key files: `assets/banner-1544x500.png`, `assets/icon-256x256.jpg`, `assets/screenshot-1.png`.

## Key File Locations

**Entry Points:**
- `wordpress-particles.php`: WordPress plugin bootstrap hooked into `init`.
- `src/index.js`: Gutenberg block registration entry.
- `src/view.js`: Frontend runtime entry for loading and instantiating particles.

**Configuration:**
- `src/block.json`: Block schema, attribute defaults, and asset linkage (`editorScript`, `viewScript`, `style`).
- `package.json`: Package scripts and dependency graph.
- `nx.json`: Nx caching defaults for build targets.
- `pnpm-workspace.yaml`: pnpm workspace-level build allowlist.
- `.editorconfig`: Formatting/editor baseline.

**Core Logic:**
- `src/load.js`: Central plugin catalog aggregation and runtime loading orchestration.
- `src/utils.js`: Common utilities used by all plugin category modules.
- `src/plugins/**/*.js`: Domain-specific dynamic import loaders.
- `src/edit.js`: Attribute editing UI and preview setup.
- `src/save.js`: Saved markup generation.

**Testing:**
- Not detected (`*.test.*` / `*.spec.*` files are not present in this package path).

## Naming Conventions

**Files:**
- Lowercase kebab-case for feature/category files: `src/plugins/updaters.js`, `src/plugins/interactions/external.js`.
- Nested domain folders for grouped concerns: `src/plugins/interactions/`, `src/plugins/plugins/`.
- WordPress-standard metadata filename: `src/block.json`.

**Directories:**
- Lowercase single-purpose directories in `src/`: `src/plugins/`.
- Subdomain directories mirror logical grouping names: `src/plugins/interactions/`, `src/plugins/plugins/`.

## Where to Add New Code

**New Feature:**
- Primary code: Add loader/catalog support in `src/plugins/` and wire into `src/load.js`.
- Editor controls: Expose toggle and attribute in `src/block.json` and rely on dynamic control generation in `src/edit.js`.
- Frontend behavior: Keep initialization in `src/view.js`; avoid adding frontend bootstrapping outside this file.
- Tests: Not applicable in current structure (no testing directory/pattern in repository).

**New Component/Module:**
- Implementation: Add category modules under `src/plugins/` or submodules under existing folders (`src/plugins/interactions/`, `src/plugins/plugins/`) and export `getX`/`handleX` pair.

**Utilities:**
- Shared helpers: `src/utils.js` for reusable catalog/handler primitives.
